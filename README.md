# sha1-go

A drop-in replacement for Go's `crypto/sha1`, tuned for x86-64 CPUs
that have SSSE3 but no AVX2 or SHA-NI.

Go 1.25 removed the scalar amd64 assembly from `crypto/sha1`, so such
CPUs run its pure Go code. This package uses SSSE3 assembly there, or
the Go 1.24 scalar assembly without SSSE3, and delegates to
`crypto/sha1` everywhere else. The API and the marshalled hash state
are identical to `crypto/sha1`.

## amd64 implementation

All amd64 assembly uses legacy SSE encodings only; nothing requires
AVX.

- The SSSE3 block function is an independent implementation of the
  technique Intel published in 2010: SSE computes the message schedule
  four words at a time, 16 rounds ahead, interleaved with the scalar
  rounds.
- Caller data is only loaded with `MOVOU`, and the stack buffer used
  with aligned stores is explicitly aligned to 16 bytes. The last block
  never reads past the input.
- The SSSE3 assembly is generated by `_asm`; run `go generate` after
  changing it.
- The scalar fallback is `blockAMD64` from Go 1.24, unchanged.

## Testing

```bash
go test ./...                  # every code path the CPU supports
scripts/test.sh                # also AVX2/SHA-NI hidden, SSSE3 hidden, -race, purego, 386
FUZZTIME=10m scripts/test.sh   # plus fuzzing against crypto/sha1
```

Every test forces each supported code path, so the SSSE3 and scalar
paths are tested on CPUs where `crypto/sha1` is used by default. The
tests cover the NIST vectors, Go's golden table, comparisons with
`crypto/sha1` for every length up to 4 KiB and random lengths up to
8 MiB, random write splits, marshalled state compatibility in both
directions, every alignment offset 0–15, inputs next to guard pages,
and code path selection under `GODEBUG=cpu.*=off`.
